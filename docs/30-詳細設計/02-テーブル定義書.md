## 1. テーブル一覧

### 1.1 認証・ユーザー関連

#### users
ユーザー情報を管理するテーブル

| カラム名 | データ型 | 制約 | 説明 |
|---------|---------|------|------|
| id | uuid | PK | ユーザーID |
| tenant_id | uuid | FK, NOT NULL | テナントID（所属テナント） |
| name | string(255) | NOT NULL | ユーザー名 |
| email | string(255) | UNIQUE, NOT NULL | メールアドレス |
| email_verified_at | timestamp | NULL | メール認証日時 |
| password | string(255) | NOT NULL | パスワード（ハッシュ） |
| role | string(50) | NOT NULL | ロール（system-admin, tenant-admin, employee） |
| remember_token | string(100) | NULL | リメンバートークン |
| created_at | timestamp | NOT NULL | 作成日時 |
| updated_at | timestamp | NOT NULL | 更新日時 |
| deleted_at | timestamp | NULL | 削除日時（ソフトデリート） |

**インデックス**:
- `tenant_id`
- `email`
- `role`

**RLSポリシー**:
- テナント分離（system-adminは全テナントアクセス可能）

## 2. 外部キー制約

### 2.1 外部キー一覧

- `users.tenant_id` → `tenants.id`
- `tenant_users.user_id` → `users.id`
- `tenant_users.tenant_id` → `tenants.id`
- `groups.tenant_id` → `tenants.id`
- `group_users.group_id` → `groups.id`
- `group_users.user_id` → `users.id`
- `punch_types.tenant_id` → `tenants.id`
- `attendance_records.tenant_id` → `tenants.id`
- `attendance_records.user_id` → `users.id`
- `attendance_records.shift_id` → `shifts.id`
- `attendance_records.punch_type_id` → `punch_types.id`
- `shifts.tenant_id` → `tenants.id`
- `shifts.user_id` → `users.id`
- （以下、同様にすべてのテーブルに外部キー制約を設定）

## 3. インデックス戦略

### 3.1 必須インデックス

- すべての`tenant_id`カラムにインデックス
- すべての`user_id`カラムにインデックス
- 日付・時刻カラムにインデックス（検索・集計用）
