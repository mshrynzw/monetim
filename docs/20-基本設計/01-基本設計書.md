## 1. システム概要

### 1.1 システム名

monetim（勤怠給与管理システム）

### 1.2 システムの目的

マルチテナント対応の勤怠給与管理システムとして、企業ごとに独立した環境を提供し、出退勤管理、勤務時間計算、給与計算、休暇管理を行う。

### 1.3 システムの特徴

- **マルチテナント対応**: 1企業 = 1テナントで完全にデータ分離
- **柔軟な設定**: テナントごとにすべての設定をカスタマイズ可能
- **PostgreSQL RLS**: データベースレベルでのセキュリティ
- **モダンなUI**: Tailwind CSS + shadcn/uiによる美しいUI

## 3. マルチテナント設計

### 3.1 テナント分離方式

**PostgreSQL RLS（Row Level Security）を使用**

- データベースレベルでテナント間のデータを分離
- アプリケーション側のミスがあっても、データベースレベルで保護
- パフォーマンスが良い（インデックスを活用）

### 3.2 テナント識別

- すべてのテーブルに`tenant_id`カラムを追加
- RLSポリシーで`tenant_id`による自動フィルタリング
- セッションに`tenant_id`を保存してテナントを識別

### 3.3 データ分離の実装

```sql
-- 例: usersテーブルのRLSポリシー
CREATE POLICY tenant_isolation ON users
    USING (tenant_id = current_setting('app.current_tenant_id')::uuid);
```

## 4. 認証・認可設計

### 4.1 認証方式

- Laravel Breezeを使用
- セッション認証
- 将来的にAPI認証（Laravel Sanctum）も対応

### 4.2 ロール設計

**system-admin（システム管理者）**:
- 全テナントの管理
- テナントの登録・編集・削除

**tenant-admin（テナント管理者）**:
- 自テナントのみ管理
- 従業員管理
- テナント設定の変更

**employee（従業員）**:
- 自分のデータのみアクセス可能

### 4.3 認可の実装

- Laravel Policyを使用
- ミドルウェアでロールチェック
- リソースごとに権限チェック

## 5. データベース設計方針

### 5.1 テーブル設計原則

- すべてのテーブルに`tenant_id`を追加
- タイムスタンプ（`created_at`, `updated_at`）を自動管理
- ソフトデリート対応（`deleted_at`）
- UUIDを主キーとして使用（セキュリティ向上）

### 5.2 リレーション設計

- 多対多リレーションは中間テーブルを使用
- 外部キー制約を使用して整合性を保証
- インデックスを適切に設定

### 5.3 RLSポリシー設計

- すべてのテーブルにRLSポリシーを設定
- `tenant_id`による自動フィルタリング
- システム管理者は全テナントのデータにアクセス可能

## 6. 機能設計

### 6.1 出退勤機能

- 打刻の種類はテナントごとに設定可能
- 1日複数回出勤（シフト制）に対応
- 日をまたぐ勤務に対応
- GPS位置情報の記録

### 6.2 勤務時間計算機能

- テナントごとに計算ルールを設定可能
- 日次・週次・月次集計
- 残業時間、深夜労働時間の自動計算

### 6.3 休暇管理機能

- テナントごとに休暇の種類を設定可能
- 柔軟な承認フロー
- 休暇カレンダー表示

### 6.4 給与計算機能

- テナントごとに給与体系を設定可能
- 給与明細の項目をカスタマイズ可能
- 自動計算と手動計算の両方に対応
