## 1. 一般原則

### 1.1 コード品質

- **可読性**: コードは読みやすく、理解しやすく書く
- **保守性**: 将来の変更に対応しやすいコードを書く
- **一貫性**: プロジェクト全体で一貫したスタイルを保つ
- **DRY原則**: 同じコードの重複を避ける

### 1.2 命名規則

- **明確性**: 変数名、関数名、クラス名は明確で意味が分かるものにする
- **英語**: すべてのコードは英語で記述する
- **コメント**: 必要に応じて日本語のコメントを追加する

### 2.4 コントローラー

- コントローラーは薄く保つ
- ビジネスロジックはサービス層に移動
- 1つのメソッドは1つの責任のみ

```php
class PunchController extends Controller
{
    public function __construct(
        private AttendanceService $attendanceService
    ) {}

    public function store(Request $request)
    {
        $validated = $request->validate([
            'punch_type_id' => 'required|uuid',
            'latitude' => 'nullable|numeric',
            'longitude' => 'nullable|numeric',
        ]);

        $record = $this->attendanceService->punch($validated);

        return response()->json($record, 201);
    }
}
```

### 2.5 モデル

- Eloquentモデルを使用
- リレーションを適切に定義
- アクセサ・ミューテータを活用

```php
class AttendanceRecord extends Model
{
    protected $fillable = [
        'tenant_id',
        'user_id',
        'punch_type_id',
        'punched_at',
    ];

    protected $casts = [
        'punched_at' => 'datetime',
        'latitude' => 'decimal:8',
        'longitude' => 'decimal:8',
    ];

    public function user(): BelongsTo
    {
        return $this->belongsTo(User::class);
    }

    public function punchType(): BelongsTo
    {
        return $this->belongsTo(PunchType::class);
    }
}
```

### 2.6 サービス層

- ビジネスロジックはサービス層に実装
- 再利用可能なメソッドを作成
- 例外処理を適切に行う

```php
class AttendanceService
{
    public function __construct(
        private AttendanceRecord $attendanceRecord,
        private ShiftService $shiftService
    ) {}

    public function punch(array $data): AttendanceRecord
    {
        // ビジネスロジック
        $record = $this->attendanceRecord->create($data);
        
        // シフトの更新
        $this->shiftService->updateShift($record);

        return $record;
    }
}
```

```typescript
export const useAttendance = () => {
    const [records, setRecords] = useState<AttendanceRecord[]>([]);

    const fetchRecords = useCallback(async () => {
        const response = await axios.get('/api/attendance/records');
        setRecords(response.data);
    }, []);

    return { records, fetchRecords };
};
```

## 4. データベース規約

### 4.1 テーブル名

- 複数形、snake_case
- 例: `users`, `attendance_records`, `leave_requests`

### 4.2 カラム名

- snake_case
- 例: `user_id`, `created_at`, `is_active`

### 4.3 主キー

- `id` (UUID)
- 自動生成

### 4.4 外部キー

- `{table}_id`形式
- 例: `user_id`, `tenant_id`

### 4.5 タイムスタンプ

- `created_at`, `updated_at`を自動管理
- `deleted_at`でソフトデリート

### 4.6 インデックス

- すべての`tenant_id`にインデックス
- すべての`user_id`にインデックス
- 検索・集計に使用するカラムにインデックス

## 5. Git規約

### 5.1 コミットメッセージ

**形式**:
```
[種類] 簡潔な説明

詳細な説明（必要に応じて）
```

**種類**:
- `feat`: 新機能
- `fix`: バグ修正
- `docs`: ドキュメント
- `style`: コードスタイル
- `refactor`: リファクタリング
- `test`: テスト
- `chore`: その他

**例**:
```
feat: 打刻機能を実装

- 出勤・退勤の打刻機能を追加
- GPS位置情報の記録に対応
- シフトの自動生成機能を実装
```

### 5.2 ブランチ名

- `feature/機能名`
- `fix/バグ修正内容`
- `refactor/リファクタリング内容`

**例**:
- `feature/attendance-punch`
- `fix/punch-validation-error`
- `refactor/work-time-calculation`

## 7. テスト規約

### 7.1 テストファイル名

- `{ClassName}Test.php`
- 例: `AttendanceServiceTest.php`

### 7.2 テストメソッド名

- `test_動作説明`
- 例: `test_can_calculate_work_time`

### 7.3 テストの構成

```php
class AttendanceServiceTest extends TestCase
{
    public function test_can_punch(): void
    {
        // Arrange（準備）
        $user = User::factory()->create();
        
        // Act（実行）
        $record = $this->attendanceService->punch([
            'user_id' => $user->id,
            'punch_type_id' => 'punch-type-id',
        ]);
        
        // Assert（検証）
        $this->assertNotNull($record);
        $this->assertEquals($user->id, $record->user_id);
    }
}
```
