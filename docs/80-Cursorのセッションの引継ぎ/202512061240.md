---

## 重要な決定事項

### 1. マルチテナント設計
- **データベース**: PostgreSQL 16を使用
- **データ分離**: PostgreSQL RLS（Row Level Security）を使用してデータベースレベルで分離
- **テナント単位**: 1企業 = 1テナント
- **ユーザーとテナント**: 1ユーザーが複数テナントに所属可能

### 2. 柔軟な設定方針
- **すべての設定をテナントごとに動的に設定可能**
- 打刻の種類、勤務時間計算ルール、休暇の種類、給与計算ルールなど、すべてテナント管理者が設定可能

### 3. 出退勤機能
- **打刻の種類**: テナントごとに設定可能（出勤、退勤、休憩開始/終了、外出/戻りなど）
- **1日複数回出勤**: シフト制に対応（1日に複数の出勤・退勤を記録可能）
- **日をまたぐ勤務**: 対応（出勤時刻を基準に勤務日を判定）

### 4. テスト戦略
- **実装と並行してテストを作成**
  - 1ソースコードファイル = 1単体テスト
  - 1機能 = 1統合テスト
- **Phase 9**: 総合テスト・最終確認（単体・統合テストは各Phaseで作成済みを前提）

## 重要な技術的決定

### PostgreSQL RLSの実装
- すべてのテーブルに`tenant_id`カラムを追加
- RLSポリシーで`tenant_id`による自動フィルタリング
- セッションに`tenant_id`を保存してテナントを識別

### 認証・認可
- Laravel Breezeを使用
- ロール: `system-admin`, `tenant-admin`, `employee`
- Laravel Policyで権限チェック

### フロントエンド
- Inertia.js + React
- Tailwind CSS + shadcn/ui
- React Hook Form + Zod（バリデーション）
